# UX Specification

## Core interaction

The application should optimise for one central action:

**Start meeting**

The user should not need to understand the product before using it.

## Home

Potential structure:

```text
MEETINGS

+ New meeting

Today
  Client Alpha
  Team Sync

Yesterday
  Discovery Call

This month
  Project Review
```

Avoid dashboards.

Avoid cards containing excessive metadata.

Avoid a sidebar that looks like a full productivity suite.

## Active meeting

Potential hierarchy:

```text
CLIENT ALPHA                         32:18
● TRANSCRIBING

────────────────────────────────────────

NOTES

pricing is still confusing
need engineering estimate
Sarah to send revised flow

────────────────────────────────────────

TRANSCRIPT

32:04  Sarah
...

32:09  Nick
...

────────────────────────────────────────

[Stop meeting]
```

The user-facing notes should have visual priority over the transcript.

The transcript is supporting evidence.

## Post-meeting

The first screen after stopping should show the useful result, not a processing dashboard.

Potential sections:

- Summary
- Decisions
- Action items
- Open questions
- Notes
- Transcript

Use progressive disclosure for transcript details.

## Keyboard-first

Important shortcuts should exist early:

- New meeting
- Start/stop
- Focus notes
- Search
- Finish/enhance
- Open command menu

The app should be usable without a mouse for common flows.

## Editing model

Prefer plain, predictable editing.

The generated notes should feel like a document, not a collection of draggable blocks.

Markdown should remain the underlying representation.

## Search

Search should become a first-class capability fairly early.

Useful query patterns:

- title
- project/client
- participant
- tag
- date
- content
- transcript
- action items

Later:
- semantic search
- natural-language questions

## Failure states

Design explicitly for:
- microphone denied
- system audio unavailable
- transcription provider unavailable
- AI provider unavailable
- laptop sleep/interruption
- network interruption
- Markdown write failure
- partially completed meeting
- duplicate meeting
- app crash/relaunch

A meeting capture tool cannot casually lose data.
